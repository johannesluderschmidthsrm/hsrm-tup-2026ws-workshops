Ziel dieses Workshops ist es, responsive Layouts mit UIkit-Grids zu verstehen, gezielt für unterschiedliche Bildschirmgrößen zu gestalten und erste kleine JavaScript-Interaktionen zu ergänzen. Außerdem vergleichen Sie wieder eine manuelle Arbeitsweise mit KI-gestützter Unterstützung.

Vorbereitung

  • Öffnen Sie Ihren Ordner tup-workshop/vorname-nachname in Visual Studio Code.
  • Benennen Sie Ihre bisherige index.html aus Workshop 1 in workshop1.html um.
  • Erstellen Sie anschließend eine neue Datei workshop2.html. Sie können dafür Inhalte und Strukturen aus Workshop 1 übernehmen und weiterentwickeln.
  • Legen Sie zusätzlich eine Datei workshop2.js in Ihrem assets-Ordner an. Diese Datei nutzen wir später für eine erste JavaScript-Interaktion.
  • Achten Sie weiterhin auf kleine Dateinamen ohne Leerzeichen, Umlaute und Sonderzeichen.

Aufgabe 1: Inhalt und Grundstruktur

Erstellen Sie eine kleine responsive Themenseite. Das Thema können Sie frei wählen, z. B. ein Medienprodukt, eine App, ein Spiel, eine Technologie, ein KI-Tool, eine Ausstellung oder ein interaktives Erlebnis.

  • Erstellen Sie eine klare Seitenstruktur mit <header>, <main> und mehreren <section>-Abschnitten.
  • Ergänzen Sie eine Hauptüberschrift, kurze Einleitung und mindestens drei Inhaltsabschnitte.
  • Nutzen Sie Bilder aus Ihrem assets/images-Ordner oder geeignete eigene bzw. frei nutzbare Bilder.
  • Ergänzen Sie mindestens eine Card-Gruppe mit mehreren kurzen Informationselementen.

Aufgabe 2: Responsive Layout mit UIkit-Grids

Bauen Sie rund um Ihre Inhalte ein responsives Layout mit UIkit-Grids. Arbeiten Sie dabei bewusst mobile first: Auf kleinen Bildschirmen sollen Inhalte gut untereinander lesbar sein; auf größeren Bildschirmen dürfen sie nebeneinander stehen.

  • Verwenden Sie die .uk-container-Klasse zum Begrenzen der Hauptspalte.
  • Verwenden Sie .uk-grid und passende Breitenklassen, um Inhalte in Spalten zu gliedern.
  • Nutzen Sie Breakpoints wie @s, @m und @l, z. B. uk-child-width-1-2@s, uk-child-width-1-3@m oder uk-child-width-1-4@l. Nutzen Sie min. zwei Breakpoints.
  • Testen Sie Ihr Layout im Browser mit unterschiedlichen Fensterbreiten und mit den Developer Tools.

Aufgabe 3: Layout verstehen und dokumentieren

Responsive Design bedeutet nicht nur, Klassen zu kopieren, sondern vorherzusagen, wie sich ein Layout bei unterschiedlichen Bildschirmgrößen verhält.

  • Wählen Sie einen Grid-Abschnitt aus Ihrer Seite aus.
  • Beschreiben Sie kurz, wie dieser Abschnitt auf Smartphone, Tablet und Desktop aussieht.
  • Ergänzen Sie diese Beschreibung direkt in Ihrer HTML-Datei als Kommentar.
  • Beantworten Sie dabei: Wie viele Spalten sind sichtbar? Wann brechen Inhalte in die nächste Zeile um?

JavaScript-Wiederholung

JavaScript wurde bereits in IMT behandelt. Im Rahmen von IM/UI wird es in der nächsten Vorlesung behandelt. Für die kleine Interaktion in diesem Workshop können Sie aber schon einmal auf die passenden Vorlesungsfolien zugreifen:

  • Folien zur Einbindung von JavaScript öffnen
  • Folien zur DOM-Manipulation öffnen
  • Relevant für diesen Workshop sind insbesondere die Grundlagen zu Selektoren, Events, classList, Einbindung von JavaScript und DOM-Manipulation.
  • Nutzen Sie die Folien als Nachschlagewerk, um die kleine JavaScript-Interaktion aus Aufgabe 4 besser zu verstehen.

Aufgabe 4: Erste JavaScript-Interaktion

Ergänzen Sie eine kleine Interaktion mit JavaScript. Ziel ist nicht komplexe Programmierung, sondern ein erster Eindruck davon, wie sich HTML-Elemente dynamisch verändern lassen.

  • Binden Sie Ihre Datei workshop2.js am Ende Ihrer HTML-Datei ein.
  • Erstellen Sie einen Button oder Link, der eine sichtbare Änderung auf der Seite auslöst.
  • Beispiel: Ein zusätzlicher Infotext wird ein- und ausgeblendet.
  • Alternativ: Eine Card erhält beim Klick eine zusätzliche Klasse, ein Hinweisbereich wird geöffnet oder ein einfacher Dark-/Light-Modus wird umgeschaltet.

Ein sehr einfaches Beispiel:

document.querySelector('#info-button').addEventListener('click', function () {
    document.querySelector('#zusatzinfo').classList.toggle('uk-hidden');
});

Arbeitsweise im Workshop: Manuell vs. KI

Arbeiten Sie wie in Workshop 1 bewusst in zwei Phasen. So können Sie vergleichen, was Sie selbst lösen können und wo KI sinnvoll unterstützt.

Phase A: Manuelles Arbeiten

  • Erstellen Sie zunächst selbst ein responsives Grundlayout.
  • Nutzen Sie dafür Ihre Vorlesungsfolien, die UIkit-Dokumentation und die Beispiele aus dem Workshop.
  • Testen Sie Ihr Layout im Browser und passen Sie es selbst an.

Phase B: Arbeiten mit KI

  • Nutzen Sie anschließend die Hochschul-KI unter ki.hs-rm.de.
  • Lassen Sie sich z. B. Ihr Grid erklären, alternative Breakpoints vorschlagen oder Ihre kleine JavaScript-Interaktion erklären.
  • Übernehmen Sie Vorschläge nur dann, wenn Sie verstanden haben, was der Code macht.

Mögliche Prompts:

  • Erkläre mir dieses UIkit-Grid. Wie viele Spalten entstehen auf Smartphone, Tablet und Desktop?
  • Schlage mir passende UIkit-Breakpoints für ein responsives Card-Layout mit sechs Elementen vor. Erkläre die Klassen kurz.
  • Erkläre mir diesen JavaScript-Code Schritt für Schritt. Was passiert beim Klick auf den Button?
  • Vereinfache diesen HTML-Code für Anfänger:innen, ohne die Funktion zu verändern.

Dokumentation (AI Production Log)

Dokumentieren Sie am Ende Ihrer Abgabe kurz Ihre Arbeit mit KI (ca. 5–10 Zeilen in einer Textdatei oder als Kommentar am Ende Ihrer Abgabe):

  • Welche Prompts haben Sie verwendet?
  • Was hat KI beim Responsive Layout gut erklärt oder verbessert?
  • Was war problematisch, zu kompliziert oder falsch?
  • Was mussten Sie selbst anpassen oder korrigieren?
